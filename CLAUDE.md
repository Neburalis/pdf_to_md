# pdf-to-md

Конвертирует PDF в Markdown через локальные GGUF-модели (llama-cpp-python, CUDA).
Pipeline: Render → Vision (Qwen2.5-VL-7B) → Merge → Clean (gemma-3-12b).

- **[PROJECT.md](PROJECT.md)** — описание проекта, команды запуска, известные нюансы, инструменты
- **[ARCHITECTURE.md](ARCHITECTURE.md)** — устройство кода, модули, CLI, зависимости; changelog архитектурных изменений в `## Changelog`
- **[AI.md](AI.md)** — модели, промпты, параметры inference, результаты тестов, паттерны галлюцинаций; changelog AI-решений в `## Changelog`

---

## Правила написания кода

- Весь консольный вывод — через `logger.get().info(...)`, не через `print()`. Это гарантирует запись в файл и корректную работу с tqdm-барами.
- Новые зависимости ставить через `UV_NATIVE_TLS=1 uv add <pkg>` (антивирус делает SSL-инспекцию). Для скачивания с HuggingFace использовать `HF_HUB_DISABLE_SSL_VERIFY=1`.
- Пути к моделям — всегда явные пути к GGUF-файлам. Ollama backend удалён и не возвращается.
- Любой вызов llama.cpp (загрузка модели, inference) оборачивать в `suppress_stdout_stderr()` из `llama_cpp._utils`.
- Vision и text модели загружаются **последовательно**, не одновременно — обе не помещаются в 12 ГБ VRAM. Перед загрузкой text-модели вызывать `unload_vision_model()`.
- Кэш страниц — файлы `page_NNNN.md` в `.pdf_to_md_cache/<sha256[:16]>/`. Не трогать без явной причины.
- Статистику и тайминги добавлять через `RunStats` (`stats.py`), не через ad-hoc переменные.
- Новые CLI-аргументы добавлять в `cli.py` и пробрасывать через `pipeline.run()`.

## Правила ведения документации

### Описывать не только текущее состояние, но и историю решений

В PROJECT.md и ARCHITECTURE.md фиксировать **не только то, как оно работает сейчас**, но и:
- Какие подходы были опробованы и отвергнуты
- **Почему** конкретное решение оказалось неудачным (конкретные симптомы, цифры)
- Почему текущее решение лучше

Это критически важно, чтобы не возвращаться к уже проверенным плохим решениям.

Пример плохой документации:
> Vision model: Qwen2.5-VL-7B

Пример хорошей документации:
> Vision model: Qwen2.5-VL-7B (заменила Qwen2-VL-7B — старая модель давала 22% галлюцинаций:
> повторяющиеся блоки контента, fake imgur URLs, heading-depth repetition)

### Вести changelog в профильных файлах

Каждое значимое изменение логировать в раздел `## Changelog` соответствующего файла:
- AI-изменения (модель, промпт, параметры inference, галлюцинации) → `AI.md`
- Архитектурные изменения (код, скрипты, pipeline, CLI, зависимости) → `ARCHITECTURE.md`

Формат записи:

```
### YYYY-MM-DD — Краткое название изменения

**Проблема:** что не работало и почему это важно  
**Решение:** что изменили  
**Результат:** измеримый эффект (цифры, примеры)  
**Отвергнутые альтернативы:** что пробовали, почему не подошло
```
